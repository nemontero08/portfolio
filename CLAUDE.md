# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

@AGENTS.md

## Goal

Rebuild this portfolio as a React/Next.js app deployed to Vercel, visually and
behaviorally faithful to the captured original, with NO dependency on Framer's
runtime. `reference/framer-original/` is the source of truth for layout, copy,
spacing, and motion.

## Rules for the rebuild

- Do not redesign, modernize, or simplify. Reproduce what the original does.
- Animations: use `motion` (`motion/react`). Do NOT reuse or port Framer's
  minified `.mjs` runtime modules — extract the animation VALUES and reimplement.
  - Scroll/load reveals → extract from `data-framer-appear-id` + the inline
    appear-animation scripts in the captured HTML.
  - Hover/interaction values are runtime-only; they'll be supplied manually
    from DevTools. Don't invent them.
- Layout: use measured values per breakpoint (375 / 425 / 768 / 1024 / 1440).
  Don't eyeball.
- Design tokens and component specs live in `reference/specs/` — read them, but
  the original HTML/CSS wins if they disagree.
- Work one component at a time: implement → `npm run dev` → compare against the
  original → commit. Then the next.

## What this repository is

A Next.js (App Router, TypeScript) app at the repository root, scaffolded but
not yet built out — `app/layout.tsx` and `app/page.tsx` are still the
create-next-app placeholders. `reference/` holds the source-of-truth material
the rebuild is copied from:

- `reference/framer-original/` — offline, browser-captured mirror of the live
  Framer portfolio ("Nico Montero"). Source of truth. Read-only.
- `reference/specs/` — extracted design tokens and component/motion specs.
  `motion-confirmed.md` (live-observed behavior) overrides
  `motion-reveals.md` and `component-motion-spec.html` wherever they disagree.

### Commands

- `npm run dev` — start the dev server (Turbopack). Port 3000 is often
  already taken on this machine; Next.js falls back to 3001 automatically —
  check the terminal output for the actual port rather than assuming 3000.
- `npm run build` — production build.
- `npm run start` — serve the production build.
- `npm run lint` — ESLint (flat config, `eslint.config.mjs`).
- No test runner is configured yet.

### Architecture

- `app/globals.css` — design tokens (colors, type scale, weights, line
  height, letter spacing, spacing scale, radii) as CSS custom properties on
  `:root`, transcribed from `reference/specs/design-system-spec.html`. Add to
  this file rather than hardcoding values in components.
- `app/layout.tsx` loads `Inter` via `next/font/google` and exposes it as the
  `--font-inter` CSS variable, referenced by `--font-family-sans` in
  `globals.css`.
- `motion` (Motion for React, `motion/react`) is installed for the reveal/hover
  animations described under "Rules for the rebuild" above — not yet wired
  into any component.
- `AGENTS.md` at the repo root is generated and kept up to date by Next.js's
  own tooling (`next dev`/`next build` rewrite it) with framework-version
  warnings; `CLAUDE.md` doesn't duplicate it — Claude Code reads it via the
  `@AGENTS.md` import convention. Don't hand-edit `AGENTS.md`'s
  framework-rules block.

## Structure of the captured mirror

`reference/framer-original/` contains three page captures and a mirrored copy of every remote asset domain the live site depended on:

- `index.html`, `how-i-work/index.html`, `vitalmed/index.html` — the three captured pages (home, "how I work", and a "vitalmed" project/case-study page). Each is a full snapshot of Framer's rendered/hydrated markup, not hand-authored HTML.
- `f2c-sw.js` — a service-worker asset manifest generated by the capture tool. It maps each original remote path (e.g. `framerusercontent.com/images/...`) to its locally mirrored file under `assets/`. This is how the offline copy resolves images, fonts, and JS chunks without hitting the network.
- `assets/` — mirrored assets, one subdirectory per source domain the live site pulled from:
  - `framerusercontent.com/` — site content: images, fonts (`.woff2`), and the compiled Framer runtime/component JS modules (`.mjs`) for this specific site.
  - `app.framerstatic.com/` — Framer's shared editor/runtime chunks (bundler-hashed `chunk-*.mjs` files); this is Framer platform code, not site-specific content.
  - `fonts.gstatic.com/`, `cdn.jsdelivr.net/`, `lottie.host/`, `events.framer.com/`, `api.framer.com/`, `framer.com/`, and a `*.framercanvas.com/` host — smaller sets of mirrored third-party/CDN assets.
  - `.git/` inside `reference/framer-original/` is an empty, uninitialized repo (no commits) — disregard it.

## Working with this content

- Treat everything under `reference/framer-original/` as **read-only reference material**, not source to modify. The HTML is generated output from Framer and the asset filenames are content-hashed by Framer's build — editing them by hand won't correspond to any real source and won't affect the live site.
- When asked to reference "the site", "the portfolio", or specific pages/sections, look in the three `index.html` files above; page content lives inline in the rendered markup (Framer sites are client-hydrated, so static structure is limited — most of the visual page is built at runtime by the `.mjs` modules in `assets/framerusercontent.com/sites/.../`).
- If asked to find a specific image, font, or script referenced by a page, resolve it through `f2c-sw.js`'s URL mapping rather than guessing a path — the on-disk filenames rarely match the original remote paths one-to-one (Framer appends content-hash suffixes and query-string variants for the same logical asset).
