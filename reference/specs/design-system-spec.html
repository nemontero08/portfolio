Nico Montero Portfolio — Design System Specification

Extracted directly from the original Framer export's compiled CSS (index.html, how-i-work/index.html, vitalmed/index.html). Values below are read from the source, not guessed. The original site is the source of truth; this formalizes what already exists — nothing here is a new visual direction.

1. Foundations & principles

  • Typography-led hierarchy — one typeface (Inter), hierarchy from size/weight only.
  • Monochrome dark base — five near-black surface steps, color reserved for one lavender accent and per-case-study tints.
  • Editorial, report-style case studies — procedural section labels ("THE PROBLEM", "CONSTRAINTS") over marketing copy.
  • Numbers as evidence — stats always paired with what they mean, never decorative.
  • Restrained borders — hairlines are inset shadows, never add layout width.
  • Large radii relative to element size — nothing sharp-cornered.
  • Motion as confirmation, not spectacle — short fades/lifts, no bounce or elaborate stagger.

6. Motion

The compiled static CSS carries no transition/box-shadow declarations — Framer drives motion via its runtime JS (Motion library), not CSS. The values below are read from the visible initial-state markup and match what's already documented in the attached design system: section reveals fade+rise (~600ms, ease-out, no bounce), hover transitions on buttons/links are short (120–200ms) color/lift changes. Treat these as a faithful approximation of the runtime behavior, not extracted spring/easing constants — the minified bundle does not expose them as readable values.

7–9. Components & states

Inventory matches what's catalogued in the bound design system (Button, LinkedInCard, Pill, SectionEyebrow, GlassCard, CaseStudyCard, TestimonialCard/slider, HowItWorkStep, HowItWorkTeaser, BackLink, LetsTalkCard) — each maps to a real repeated pattern verified against all three exported pages, not invented. No new components are proposed here.

10–11. Responsive & interaction patterns

Same as documented in the attached design-system guide: hover lightens one surface step (bg-2→bg-3) and/or lifts 1–2px; the Resume tile's arrow nudges up-right; the LinkedIn tile's flourish draws in via stroke animation; the How I Work circular button fills solid on hover; case-study tiles darken their tint slightly on hover. No color inversion, no shrink-on-press.

12. Caveats

  • Motion timing/easing are approximated from markup, not extracted from the minified Framer Motion runtime.
  • Per-breakpoint pixel overrides exist in the hundreds across the export; this spec captures the five tier boundaries, not every override.
  • Fonts are served via Google Fonts Inter, not the original per-glyph split .woff2 files Framer generated — visually identical, not byte-identical.
